### Terminology

- **Writer**: The single producer process/thread responsible for writing messages into the Circular Buffer.
- **Reader**: A consumer process/thread that reads messages from the Circular Buffer. Multiple readers are supported.
- **L**: The total size (in bytes) of the Circular Buffer.
- **Position**: A zero-based byte offset within the Circular Buffer, indicating where a write or read operation is currently taking place. `position < L`.
- **Limit**: Free Space in the Circular Buffer for the Writer to write new messages without overwriting unread data. `limit <= L`.
- **Writer Position**: The current byte offset in the Circular Buffer where the Writer will write the next message.
- **Reader Position**: The current byte offset in the Circular Buffer where a Reader will read the next message when Writer Sequence increased.
- **Sequence**: A monotonically increasing message count. This is distinct from a Position and is used for high-level synchronization between the writer and readers. There is only one Writer Sequence shared among all Readers.

### Synchronization Mechanism

Writer Sequence is an `atomic<uint64_t>` counter that is incremented by the Writer each time a new message is written into the Circular Buffer, including empty messages known as Wraparound Markers.

The Writer Sequence starts at `0`, indicating that no messages are available to read. Readers wait for the Writer Sequence to increment before reading the next message from the Circular Buffer.

### Backpressure and Overwrite Prevention

The Writer keeps track of the `limit`. The `limit` is calculated as follows:

- The Writer calculates the Backpressure Position (`backpressure_position`). `backpressure_position >= position && backpressure_position <= L`.
- If `backpressure_position > position`, than `limit = backpressure_position - position`, -- the space up to the slowest lagging Reader.
- If `backpressure_position == L`, this means that all Readers are able to keep up with the Writer and `limit = L - position`, -- the remaining space to the end of the Circular Buffer.
- If `backpressure_position == position`, -- there is no space to write a new message, the Writer has to wait until the Slowest Reader advances its Reader Position.

How `backpressure_position` is calculated:

- The Writer iterates through all Reader Positions and finds the Minimum Reader Position which is greater than or equal to its own Writer Position (`position`).
- If no such Reader Position is found, it means that all Readers are able to keep up with the Writer and `limit = L - position`. Return `L` as `min_lagging_reader_position`, to allow writing up to the end of the Circular Buffer.

### Circular Buffer Wraparound

The Writer starts with:

- `position = 0`
- `backpressure_position = L`, -- all Readers are able to keep up with the Writer.
- `limit = L`, -- the size of the Circular Buffer.

Buffer Wraparound happens when one of the following conditions is met:

1. The Writer reaches the end of the Circular Buffer and needs to continue writing messages from the beginning of the Circular Buffer again.
2. There is not enough space in the Circular Buffer to write the entire messsage without a wraparound.

If one of the above conditions is met, the Writer initiates a Wraparound procedure:

1. The Writer marks the end of buffer with a Wraparound Marker:
    - The Writer writes an empty message, 2 bytes: `[0x00, 0x00]`, this is the length of the empty message. Empty message marks the end of buffer and signals to Readers that they need to wraparound as well.
    - If there is less than 2 bytes available in the buffer, the Writer will not be able to write an empty message into it. This is fine. The Wraparound Marker is either an empty message or less than 2 bytes remaining/available in the buffer, this is how Readers should be able to identify the wraparound condition.
2. The Writer increments the Writer Sequence to signal to Readers that a new message (a Wraparound Marker in this case) is available in the Circular Buffer.
3. The Writer sets its `position` to `0`.
4. The Writer recalculates `backpressure_position` and `limit` based on the new `position`.
5. The Writer waits until there is enough `limit` to write the entire message at the beginning of the Circular Buffer.

## Decision

Use the mechanism described above.

## Consequences

Lock-free message queue, lock-free Writer and Readers synchronization.

This new approach addresses the False Sharing issues of the previous approach described in [ADR003.md](ADR003.md).
